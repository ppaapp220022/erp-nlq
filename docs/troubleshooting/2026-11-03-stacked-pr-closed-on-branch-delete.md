# 쌓인 PR이 기준 브랜치 삭제와 함께 닫혔다

- **상황:** PR 8개를 쌓아 두고 #1을 `gh pr merge --merge --delete-branch`로 머지했다. 그러자 #1 브랜치를 기준으로 하던 #2가 main으로 옮겨지지 않고 **닫혔다(CLOSED)**.
- **원인:** 처음에는 GitHub이 지워진 기준 브랜치의 PR을 자동으로 main으로 옮겨 준다고 생각했다. 실제로는 이 경우에 기준 브랜치가 사라지면서 그 위 PR이 닫혔다.
- **시도:**
  - 브랜치를 커밋에서 되살리고 #2를 다시 연 뒤 `gh pr edit --base main`을 실행했다. GitHub이 504 오류를 냈다.
  - 그런데 다음 줄의 브랜치 삭제는 별도 명령이라 그대로 실행됐다. 기준이 바뀌지 않은 상태에서 브랜치가 다시 지워졌고, #2가 **또 닫혔다**.
- **해결:**
  - 다시 되살리고 연 뒤 `gh api -X PATCH .../pulls/2 -f base=main`을 재시도와 함께 실행했다.
  - 기준이 main인 것을 확인한 뒤에만 브랜치를 지웠다.
  - #2~#5는 "위 PR 기준을 main으로 바꾸고 확인 → 머지와 삭제" 순서로 처리해 모두 머지했다.
- **배운 점:** 되돌리기 어려운 단계(브랜치 삭제)는 앞 단계가 성공했는지 확인한 뒤에만 실행해야 한다. 여러 줄을 한 번에 실행할 때 앞 명령의 실패가 뒤 명령을 멈추지 않는다.

절차는 [pr-workflow.md](../pr-workflow.md) "쌓인 PR"에 정리했다.

**후속:** 레포 설정에서 "머지 후 브랜치 자동 삭제"를 켰다. 이 설정으로 지워진 브랜치를 기준으로 하던 PR은 GitHub이 main으로 옮겨 준다. 같은 날 머지 방식도 스쿼시만 쓰도록 바꿨다.
