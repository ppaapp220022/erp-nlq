# 새 영업 사원의 송장 수가 Odoo와 SQL에서 달랐다

- **상황:** 영업 사원 3명을 새로 만들고 주문·송장 담당자를 나눴다. 사용자별로 Odoo ORM이 보여 주는 수와 SQL로 센 수를 비교했다. 주문은 모두 같았다. 그런데 새 사용자의 송장은 ORM 6건, SQL 13건으로 달랐다. 기존 데모 영업 사원(Marc Demo)은 13건으로 같았다.
- **원인:** 처음에는 송장 담당자 규칙을 잘못 옮겼다고 생각했다. 실제로는 **회사 조건**이 원인이었다. 데모 데이터에는 회사가 3개 있고 송장은 두 회사에 나뉘어 있다. Odoo는 담당자 규칙과 함께 `company_id IN (사용자가 속한 회사)`를 건다. Marc Demo는 회사 3개에 모두 속해 있었고, 새 사용자는 기본 회사 하나에만 속해 있었다. 주문이 맞았던 이유는 주문 24건이 모두 한 회사에 있었기 때문이다.
- **시도:** `ir.rule._compute_domain('account.move', 'read')`를 사용자별로 출력해 비교했다. 두 사용자의 도메인은 `company_id in [3, 2, 1]`과 `[1]`만 달랐다.
- **해결:** 시드 스크립트가 새 사용자의 그룹과 회사(`company_ids`, `company_id`)를 Marc Demo와 똑같이 맞추도록 했다. 비교 SQL에도 회사 조건을 넣었다. 그 결과 4명 모두 주문과 송장 수가 ORM과 SQL에서 일치한다.
- **배운 점:** Odoo의 행 범위는 담당자 규칙만이 아니라 **멀티 회사 조건까지 합친 것**이다. 이번에 주문이 맞은 것은 데이터가 우연히 한 회사에만 있었기 때문이다.

M3 guard 설계에 반영했다([architecture.md](../architecture.md) "신원과 역할"). 우회 테스트에도 "다른 회사 문서 조회"를 넣는다.
