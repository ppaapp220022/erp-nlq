# 0004. 예시 검색: 메모리 색인, 역할로 거른 뒤 고르기

- 상태: 채택
- 날짜: 2026-11-07

## 맥락

M5 "검색 비교"는 질문과 비슷한 질문→SQL 예시를 골라 프롬프트에 넣고, 키워드 검색과 임베딩 검색을 같은 50문항으로 비교한다. 정해야 할 것은 넷이었다.

1. 색인을 어디에 둘지. DB에 pgvector 0.8.7이 이미 있다.
2. 임베딩 모델. 외부 API 키 없이 돌아야 하고, 질문이 한국어다.
3. 예시를 프롬프트 어디에 넣을지. 시스템 프롬프트는 역할마다 캐시된다.
4. 역할 밖 테이블을 쓰는 예시를 어떻게 다룰지. 열 목록과 OKF 문서는 이미 역할로 거른다(#34).

## 결정

- **색인은 프로세스 메모리에 둔다.** 예시는 `eval/examples/`의 YAML 40개이고, 처음 검색할 때 읽어 벡터를 만든다. 40개를 전부 비교해도 질문 하나에 임베딩 약 3.5ms, 키워드 약 0.3ms다(이 노트북, 모델 적재 뒤).
- **임베딩 모델은 fastembed의 `sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2`다**(384차원, ONNX, 약 240MB). 모델 파일은 처음 쓸 때 받아 `.cache/fastembed`(git 제외)에 둔다. 처음 고른 `multilingual-e5-small`은 fastembed 0.9.0이 지원하지 않는다. 지원 목록의 다국어 문장 임베딩 모델(트랜스포머) 중 가장 작은 것을 골랐다. `potion-multilingual-128M`은 정적 임베딩이라 문맥을 보지 않아 뺐다.
- **키워드 검색은 질문 글자 2-gram의 BM25다.** 한국어는 조사가 붙어 단어 단위로는 "주문"과 "주문을"이 맞지 않는다. 형태소 분석기는 의존성이 커서 쓰지 않는다.
- **예시는 사용자 메시지에 넣는다.** 질문마다 달라서 시스템 프롬프트에 넣으면 캐시가 깨진다.
- **역할로 먼저 거르고 그 안에서 고른다.** 예시 SQL이 쓰는 테이블(sqlglot으로 뽑음)을 모두 `can_read`할 수 있는 예시만 후보다. CTE 이름도 테이블로 세므로, 모르는 이름이 있으면 예시가 빠진다(실패 시 닫힘). 거르기는 노출을 줄이는 장치이고 권한은 여전히 `execute()`가 강제한다.
- 기본값은 `NLQ_RETRIEVE=keyword`다. 같은 날 Haiku로 여섯 조합을 세 번씩 재서 OKF + 키워드가 가장 높고 흔들림도 없었다(48/50 세 번). 임베딩은 검색 없음과 차이가 없었다. 숫자는 [plan.md](../plan.md) "M5 검색 비교".

## 고려한 대안

- **pgvector에 저장.** 예시가 수천 개가 되거나 여러 프로세스가 색인을 나눠 써야 할 때 맞다. 지금은 표·적재 스크립트·`nlq_readonly` 권한이 늘고, 질의 계층이 `execute()` 말고 DB에 닿는 길이 하나 더 생긴다(절대 규칙 1). 예시가 늘면 다시 본다.
- **Claude·외부 임베딩 API.** 키와 비용이 늘고, 평가를 오프라인으로 다시 돌릴 수 없다.
- **`multilingual-e5-large`.** fastembed가 지원하지만 약 2.2GB다. 40개 예시를 비교하는 데 쓰기에는 크다.
- **역할을 보지 않고 고른 뒤 거르기.** 상위 k개가 모두 읽을 수 없는 예시면 예시가 0개가 된다. 먼저 거르면 읽을 수 있는 것 중 가장 가까운 k개가 들어간다.

## 결과

- 검색 품질은 이 작은 모델의 한계를 그대로 받는다. 측정에서 임베딩은 영역이 다른 예시를 자주 골랐다(출고 질문에 회계 예시, 미수금 질문에 재고·판매 예시). 질문 문장이 짧고 업무 용어가 겹쳐 글자 2-gram이 더 잘 맞았다. 예시가 늘거나 질문이 길어지면 다시 잰다.
- 임베딩 검색을 켜면 첫 질문에서 모델을 적재한다. 파일을 처음 받을 때 약 26초, 받은 뒤에는 약 1.6초다. `nlq-eval`은 스레드를 띄우기 전에 한 번 적재한다.
- 새 의존성: `fastembed==0.9.0`과 onnxruntime·numpy·tokenizers·huggingface-hub. 두 주가 안 된 전이 의존성(filelock, hf-xet, onnxruntime)은 `[tool.uv] constraint-dependencies`로 그 앞 버전에 묶었다.
- CI에는 모델 파일이 없어 임베딩 테스트를 건너뛴다. 키워드 검색과 역할 거르기 테스트는 CI에서도 돈다.
