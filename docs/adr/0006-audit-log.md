# 0006. 감사 기록: execute()에서 남기고, 질문 원문과 값은 남기지 않는다

- 상태: 채택
- 날짜: 2026-11-08

## 맥락

plan.md의 완료 기준은 "질문·SQL·사용자·시간 기록, 개인정보 제외"다. 절대 규칙 6은 로그와 감사 기록에 개인정보를 남기지 못하게 한다. 정해야 할 것은 다음이다.

1. 어디서 남기나. CLI, 평가, 화면 API가 모두 DB에 닿는다.
2. 질문과 SQL에 섞인 개인정보(고객 이름, 이메일, 전화번호)를 어떻게 빼나.
3. 어디에 쓰나. 질의 계층의 DB 역할은 읽기 전용이다.
4. 기록하지 못하면 어떻게 하나.

## 결정

- **`execute()`에서 남긴다.** DB에 닿는 길이 `execute()` 하나뿐이라(절대 규칙 1), 여기서 남기면 CLI·평가·화면·자기 수정 재시도가 빠짐없이 남는다. guard 거부와 실행 실패도 남긴다.
- **남기는 것:** 시각(UTC), Odoo uid, 행 범위 방식(`guard|rls|both`), 결과 종류(`ok|guard_rejected|timeout|error`), 문자열 리터럴을 `'?'`로 바꾼 SQL, 결과 행 수와 잘림 여부, 걸린 시간.
- **남기지 않는 것:**
  - **질문 원문.** 자유 텍스트라 고객 이름 등을 걸러 낼 방법이 없다. 계획의 "질문 기록"과 다르다. 질문이 무엇을 물었는지는 가린 SQL(테이블, 열, 조건 구조)로 대신한다.
  - **SQL의 문자열 값.** `'...'`, `$$...$$`, `E'...'`, `x'...'`, `U&'...'`, `N'...'`, jsonb 경로 키를 모두 `'?'`로 바꾼다. 바꾼 결과를 다시 토큰으로 나눠, `'?'`가 아닌 문자열이 남아 있으면 SQL 자체를 남기지 않는다. 해석하지 못한 SQL도 남기지 않는다. 숫자는 남긴다(uid, 금액 조건 등).
  - **결과 값과 오류 문구.** DB 오류 첫 줄에는 행의 값이 섞일 수 있다(형 변환 실패한 이름). 종류만 남긴다.
  - **login.** Odoo에서 login이 이메일인 설정이 흔하다. uid만 남긴다.
- **JSON Lines 파일에 쓴다.** `NLQ_AUDIT_LOG`, 기본 `logs/audit.jsonl`(git 제외). 한 줄이 한 시도다.
- **기록하지 못하면 결과를 돌려주지 않는다(실패 시 닫힘).** 결과를 돌려주기 전에 쓰고, 쓰기에 실패하면 `AuditError`가 결과 대신 올라간다.

## 고려한 대안

- **DB 테이블에 쓰기:** 질의 계층 역할에 쓰기 권한을 줘야 한다. 읽기 전용 역할 하나로 DB에 닿는다는 경계가 흐려진다. 쓰기 전용 역할을 따로 두면 접속이 둘이 된다.
- **질문을 해시로 남기기:** 짧은 질문은 추측해서 해시를 맞춰 볼 수 있어 개인정보를 뺐다고 하기 어렵다. 쓸 곳도 마땅치 않다.
- **API 계층에서 남기기:** CLI와 평가가 빠진다. 감사의 대상은 DB에 닿은 시도다.
- **이름 사전으로 질문 걸러 내기:** `res_partner` 이름 목록을 들고 있어야 하고, 사전 밖의 이름은 걸러지지 않는다.

## 결과

- 누가 언제 어떤 구조의 SQL로 무엇을 읽으려 했는지, guard가 무엇을 막았는지는 남는다. 정확히 어떤 값으로 조회했는지는 남지 않는다.
- 파일이라 변조를 막지 못한다. 1인 데모 범위에서는 감수한다. 운영으로 가면 추가만 가능한 저장소가 필요하다(2차 목록).
- 테스트는 `tests/conftest.py`가 기록을 임시 파일로 보낸다. `test_audit.py`가 문자열 표기마다 가려지는지, 평가·예시 SQL이 모두 기록되는지, 쓰지 못하면 닫히는지 본다.
