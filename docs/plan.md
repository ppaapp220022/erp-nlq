# 개발 계획 (1인)

> **현재 위치:** M1. 인프라와 읽기 전용 역할까지 끝났다. 다음은 영업 사원 데이터 준비와 스냅숏이다.
>
> 작업이 끝날 때마다 이 줄과 아래 체크박스를 갱신한다.

원본 기획은 개인 드라이브의 "ERP 자연어 질의 시스템 기획안 (1인)"이다. 이 문서는 그중 개발에 필요한 부분만 옮긴 것이며, 레포에서는 이 문서가 기준이다.

**기간은 정하지 않는다.** 마일스톤 순서와 점검 기준만 지킨다. 앞 마일스톤의 점검을 통과하지 못하면 다음으로 넘어가지 않는다.

## 범위

- **1단계 (반드시):** 이것만 있어도 결과 표와 화면이 나온다.
- **2단계 (차별점):** 검색, 되묻기, RLS 비교 등.
- 3단계 기능(결과 마스킹, 오픈 모델 비교, MCP 서버, Odoo 애드온, 의미 계층, 문서 RAG, LoRA)은 **하지 않는다.** 아래 "2차 목록"에만 적는다.
- M4(1차 마감) 이후 떠오른 새 기능도 2차 목록으로 보낸다.

## 미리 알고 있는 위험

| 위험 | 대응 |
|---|---|
| 데모 데이터 날짜가 실행일마다 바뀜 | 스냅숏, "오늘 날짜" 고정값 |
| 평가 질문이 예시에 섞여 점수가 부풀려짐 | `eval/questions/`와 `eval/examples/` 분리 |
| `set_config`, `pg_sleep` 등 위험 함수 | guard 함수 허용 목록, 우회 테스트에 포함 |
| RLS가 Odoo 동작을 깨뜨림 | `nlq_readonly`에만 정책 적용, `FORCE` 금지 |
| 채점 오판 (행 순서, 열 이름, 반올림) | 비교할 때 무시 |
| 평가를 반복할수록 API 비용이 쌓임 | 개발 중에는 Haiku, 결과 표용 측정만 Opus. 평가 전용 키에 월 한도 |
| "Odoo ORM API를 쓰면 권한이 자동 적용되지 않나"라는 반론 | SQL을 택한 이유를 ADR로 남김 |
| 하루 이상 막힘 | 범위를 줄이거나 우회로를 택하고 troubleshooting에 기록 |
